## 数值失败及诊断

在预定的case0/patch0、True Boundary残差，原历史精度下，Oracle方向导数为0.0012948181；t=0.01中心差分为0.0017113648，绝对误差0.0004165467，超过事先固定容差0.0000847409。t=0.001误差更大。不能把原有限差分验证标记为通过。

运行环境历史配置启用了cuDNN和matmul TF32。独立的封存后数值诊断只改变计算精度，没有调整候选、残差、GT选择、t或容差：

|方向|精度|t|Autograd方向导数|中心差分|绝对误差|固定容差通过|
|---|---|---:|---:|---:|---:|---|
|True|历史TF32|0.01|0.0012948181|0.0017113648|0.0004165467|否|
|True|严格FP32|0.01|0.0013041173|0.0013035765|0.0000005408|是|
|Non-Boundary|历史TF32|0.01|-0.0003489131|0.0003732050|0.0007221180|否|
|Non-Boundary|严格FP32|0.01|-0.0003459010|-0.0003449151|0.0000009859|是|

严格FP32下Non-Boundary的t=0.001仍未通过固定容差，不能只报告成功的t。详细前向/中心差分均见numerical_precision_diagnosis/precision_comparison.csv。严格FP32的基准Boundary CE约0.64629912，历史TF32约0.64631921，二者并非数值相同的推理结果，因此不能拿严格FP32预测替换已封存的历史精度候选。

这些观测支持“小扰动有限差分受到TF32数值精度影响”的解释；尚不能把它当作所有patch的梯度验证，也没有完成D1-A/B/C病例级统计。
